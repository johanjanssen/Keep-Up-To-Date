Chapter 08

Update OS Dependencies

What to Update

  • 🐳Docker base images: your FROM line
  • 💻Virtual machine images: the OS your servers boot
  • ⚙️Installed software: runtimes and packages like openssl

Update FROM in Dockerfiles

  • 📅Treat the base image like any dependency: bump it on a schedule
☕ Java example 
- FROM eclipse-temurin:21-jre
+ FROM eclipse-temurin:25-jre
One line: new JVM, security patches and OS packages.

Pin the Version

  • 🔁Reproducible builds
  • ⏪Rollback
  • 🐞Debugging
  • 📋Auditability

Pinned doesn't mean frozen: let a bot bump the pin.

Docker Tags Aren't Truly Immutable

✅ Package registries: release = immutable

Maven Central, PyPI, npm: a published version never changes

❌ Docker: a tag can move

Same name, different bytes

The digest is immutable: FROM eclipse-temurin:25-jre@sha256:…

The Automation Flywheel

🔁 Hands-off updates every release, on repeat
1 🤖 Bot detectsa new version
2 📬 Opens a PRchangelog + diff
3 🧪 CI runsbuild, unit + integration tests, image scan
4 🟢 All greenand a low-risk update
5 🔀 Auto-mergedin ~30 minutes
6 ✅ Doneyou never touched it

Policy as Code

🔧 Renovate config, checked into the repo

// renovate.json5 (plain renovate.json doesn't allow comments)
{
  "extends": ["config:recommended"],
  "packageRules": [
    {
      "description": "Group all Docker base-image bumps: one PR, one review",
      "matchDatasources": ["docker"],
      "groupName": "Docker base images",
      "schedule": ["every weekend"]
    },
    {
      "description": "Auto-merge patch-level base image bumps once CI is green",
      "matchManagers": ["dockerfile"],
      "matchUpdateTypes": ["patch"],
      "automerge": true
    }
  ],
  "vulnerabilityAlerts": {
    "labels": ["security"],
    "automerge": true   // immediate: security patch + green CI = merged
  }
}
