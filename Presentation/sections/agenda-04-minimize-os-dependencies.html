Reduce Attack Surface with Minimal Images

  • 🧹Fewer packages: no shell, no package manager, no extra tools
  • 🔒Less access: no SSH, run as a non-root user
  • 🧱Start from scratch or distroless and add only what you need
  • 🏗️Multi-stage builds: compilers and build tools never reach prod
  • 📉Fewer packages, fewer CVEs to triage and patch

⚠ Choosing a base image is a security decision.

Trim the Runtime

  • 📦Standard runtimes ship every module, used or not
  • ✂️Strip what your app never touches
  • 🌍Java jlink · .NET trimming · Node.js --omit=dev

Vendor JRE vs. Custom jlink Runtime

☕ Java example

Vendor JRE image

  • 📦All standard modules: bigger image
  • ⚡Vendor tuning, e.g. a pre-built CDS archive
  • ✅Zero build effort

Custom jlink runtime

  • ✂️Only the modules you use: smaller image
  • ⚠️You own the build step
  • 🕵️Missed a reflection-only module? Runtime failure

Building a Custom jlink Runtime

Two commands: find what you use, then link only that

☕ Java example 
# 1. Find the JDK modules the app needs (e.g. java.base,java.logging,java.sql)
jdeps --print-module-deps --ignore-missing-deps \
      --multi-release 21 app.jar > modules.txt

# 2. Build a slim runtime containing only those modules
jlink --add-modules "$(cat modules.txt)" \
      --strip-debug --no-header-files --no-man-pages \
      --output custom-jre
