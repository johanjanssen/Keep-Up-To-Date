Chapter 10

Update Source Code

Beyond the Version Bump

  • 🔢Chapters 8 and 9 covered bumping version numbers
  • 💥Some upgrades also break your source code: renamed packages, removed APIs, changed method signatures
  • 🤖A dependency bot can open the PR, but it can't rewrite your code: that needs a dedicated migration tool

🛠️ What Is OpenRewrite?

A refactoring engine, not a text-based find/replace

  • 🌳Parses your code into a full AST with types resolved, so recipes understand semantics, not just text patterns
  • 📦Recipes compose: a big migration (e.g. "upgrade to Spring Boot 4") is really hundreds of small, independently-tested recipes chained together
  • 🔍Every recipe can run in dry-run mode first, so you review a diff before anything is applied
☕ Languages & formats Java, Kotlin, Groovy, XML, YAML, JSON, Properties files, Protobuf, plus early Python support. Curated recipe libraries exist for Spring, Jakarta EE, JUnit, Hibernate, Micronaut, Quarkus, and more.

🛠️ Alternatives to OpenRewrite

Within the JVM, and beyond it

  • ☕Error Prone + Refaster (Google): compile-time bug-pattern checks, plus template-based Java-to-Java rewrites
  • 🏢Moderne: the commercial platform built on OpenRewrite itself, for running recipes org-wide across thousands of repos at once
  • 🖱️IDE-assisted migrations (e.g. IntelliJ IDEA's structural search/replace and migration inspections): powerful, but manually triggered per project, not CI-automatable

Every other ecosystem has its own equivalent: see the alternatives table at the end of this chapter.

Automate the Migration Itself

When a framework or language version change requires code edits, automated migration tools can apply the changes: consistently and at scale across your whole codebase.

☕ OpenRewrite (Java) Recipe-driven, AST-level refactoring. No pom.xml plugin config needed: the plugin and its recipes are supplied entirely on the Maven command line.
